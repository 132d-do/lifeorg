# 系统设计

## 分层与不变量
展示层只读取公共角色契约和业务状态；应用服务负责所有权、幂等、会议生命周期；Agent 内核读取服务端核验的证据快照，不直接写业务表。D1 持久化与审计保持现有结构。

所有用户交互有明确结果：导航进入真实路由，表单返回持久化结果，滑块/开关显示保存状态。无记录时引导建立真实资料，不生成个人事实。复杂决策召集全部专家；日会可明确只召集运营，不能假称四人讨论。

## 角色契约
幕僚长负责材料检查、议程与综合；战略负责价值一致性和可比较替代路径；运营负责容量、依赖和最小行动；审计负责反证、可逆性和停止条件。展示职责与服务端指令来自同一契约。专业评议结构包含角色专属分析项，证据只能引用本轮授权记录。

## 功能验收映射
首页→真实待审批会议/首个行动入口；目标→详情/编辑/会议/周期；会议→准备/补问/评议/审批；决策→备选方案/证据/复盘；洞察→源会议和目标；设置→章程/专职角色详情/OpenAI 状态。返回、刷新、深链接保持语义。

## 兼容与风险
旧消息仍可读取；新专业输出严格校验。已运行周期时不偷偷替换承诺；建议关联现有周期并在批准前校验状态。离线保留人工记录和行动周期入口。缺少密钥、平台浏览器限制需单独报告，不能等同于业务实现失败或发布成功。
